# LocalAssistant

Локальный голосовой помощник для Windows. Слушает **системный звук** и, по желанию, **микрофон**, распознаёт речь (faster-whisper), решает, обращена ли фраза к помощнику, и отвечает через **Ollama**. Умеет опираться на ваши документы и сохранённые заметки (локальная база знаний), озвучивать ответы и жить в системном трее.

По умолчанию всё работает на вашем компьютере. Если в настройках указан **удалённый** адрес Ollama, на этот сервер уходят сообщения, контекст и фрагменты документов — выбирайте такой адрес, только если доверяете его владельцу.

Версия указана в файле `VERSION`, в окне «О программе» и в заголовке диагностики · Python 3.12 · PySide6 · история изменений — в [CHANGELOG.md](CHANGELOG.md).

## Установка

### Вариант А. Готовая сборка

В GitHub Actions каждая сборка публикует артефакт `LocalAssistant-Windows-<версия>` (папка с `LocalAssistant.exe`). Распакуйте его в любое место и запустите `LocalAssistant.exe`. Необязательное задание CI собирает также установщик `LocalAssistant-Setup-<версия>.exe` (ярлык в меню «Пуск», деинсталлятор, галочка автозапуска; администратор не нужен). Модели Whisper в сборку не входят и скачиваются при первом запуске, поэтому нужен интернет.

### Вариант Б. Из исходников

**1. Python и Ollama.** Рекомендуется **Python 3.12 x64** с включённым Python Launcher (`py`) и Ollama для Windows.

```powershell
ollama list                    # какие модели уже есть
ollama pull qwen3-coder:30b    # модель ответов по умолчанию (можно выбрать другую)
```

Ollama обычно запускается в фоне сама. Если нет — откройте её из меню «Пуск». Команду `ollama serve` используйте, только если сервер ещё не работает: занятый порт `11434` значит, что он уже слушает.

**2. Проект.**

```powershell
cd "$HOME\Desktop"
git clone https://github.com/S1nuso1d/LocalAssistantRefactor.git LocalAssistant
cd .\LocalAssistant
git switch master
```

Если папка уже существует, не клонируйте поверх неё: выполните в ней `git pull --ff-only origin master`.

**3. Зависимости.** Дважды щёлкните `setup.bat` (создаст `.venv` на Python 3.12 и установит всё из `requirements.txt`). Активация окружения не нужна.

**4. Запуск.** `run.bat` — без окна консоли. Для диагностики с видимой консолью: `.\.venv\Scripts\python.exe .\main.py`.

При первом запуске faster-whisper скачает выбранную модель. После запуска значок появится в области уведомлений; если его не видно, нажмите стрелку `^` рядом с часами.

## Как приложение живёт на компьютере

- **Значок в трее, а не на панели задач.** У окна нет кнопки на панели задач, и оно не появляется в Alt+Tab. Клик по значку показывает или скрывает окно, правый клик открывает меню (показать/скрыть, пауза прослушивания, озвучка, настройки, выход).
- **Кнопка «закрыть» сворачивает в трей**, и приложение продолжает слушать. Полностью выйти: «Выход» в меню трея или «Выйти из приложения» в меню окна. Поведение можно изменить в настройках.
- **Одна копия.** Повторный запуск не создаёт второе окно, а показывает уже работающее.
- **Автозапуск** вместе с Windows сразу в трей (без прав администратора): Настройки → Окно. Запуск свёрнутым: ключ `--tray` или пункт «Запускать свёрнутым в трей».
- Приложение не мешает выключению и выходу из Windows.

## Невидимость при трансляции экрана

Включено по умолчанию: Настройки → Окно → «Скрывать окно от записи и демонстрации экрана». Используется системная функция `SetWindowDisplayAffinity`: окна исключаются из программного захвата (OBS, Zoom, Teams, Discord, запись и снимки Windows).

**Что скрывается.** Все окна приложения, а не только главное: меню, настройки, история, журнал фильтра, база знаний, диагностика, подсказки, всплывающие списки. Защита применяется в момент создания окна, до его появления на экране. Реальный режим читается обратно у Windows и показан в «Настройки → Окно → Статус защиты» и в «О программе».

**Дополнительные меры.**
- Выбор документов для базы знаний и экспорт диалога открываются диалогом Qt, а не встроенным диалогом Windows (тот — отдельное окно ОС, защита его не видит).
- «Скрыть окно» (горячая клавиша, трей, кнопка) закрывает и открытые диалоги, а не только главное окно. Диалог, которому нужно завершить работу (например, идёт импорт документа), закроется сразу после неё.
- Перед открытием папки данных в Проводнике приложение предупреждает, что Проводник — окно другой программы, видимое при трансляции.

**Что не скрывается — важно знать:**
- Нужна Windows 10 версии 2004 или новее. На более старых окно в записи станет **чёрным прямоугольником** (статус это покажет).
- **Значок в трее и панель задач принадлежат Windows** и видны, если вы транслируете *весь экран*. Показывайте отдельное окно или вкладку, перетащите значок в скрытую область (стрелка `^`) или отключите показ значка в настройках (тогда окно возвращается только горячей клавишей; если она не зарегистрировалась, значок всё равно показывается).
- Окна других программ, которые запускает приложение (Проводник, браузер), защита не охватывает.
- Камера, направленная на монитор, и аппаратная карта захвата записывают то, что реально выводится на экран, — программно это не скрыть.
- Озвучка слышна в системе. Если не нужна — оставьте её выключенной.

**Проверьте на своём способе трансляции до важного использования:** запустите демонстрацию экрана, покажите окно, меню, настройки и диалоги, убедитесь, что их нет в трансляции. Пошаговый список — в [docs/MANUAL_QA.md](docs/MANUAL_QA.md).

Скрытие от записи — инструмент приватности. Если вы используете помощника там, где правила запрещают помощников (экзамен, собеседование), ответственность за соблюдение этих правил лежит на вас.

## Возможности

**Голос и ответы**
- Захват системного звука (SoundCard loopback) и, опционально, физического микрофона; источники работают независимо или вместе.
- Распознавание faster-whisper на CPU или CUDA; любые имена моделей и коды языков Whisper.
- Двухступенчатый фильтр фраз: правила, затем локальная модель-классификатор для неоднозначных. Режимы «сбалансированный» и «быстрый», защита от «галлюцинаций» Whisper и повторов. «Журнал фильтра» показывает, почему фраза принята или пропущена, и позволяет отправить её вручную.
- Потоковые ответы Ollama, остановка и повтор генерации, скрытие блоков `<think>`, копирование блоков кода.
- История ограничивается по токенам, в статусе видны скорость и заполнение контекста; прогрев модели и повторная проверка Ollama.
- Диалоги в SQLite: создание, переключение, поиск, переименование, удаление, экспорт в Markdown.
- Офлайн-озвучка через Windows SAPI (голос, скорость, громкость) с защитой от обратной связи.

**Windows**
- Трей, автозапуск, единственный экземпляр, корректное завершение, защита окон от захвата экрана.
- Слежение за устройствами: при смене устройства вывода или потере выбранного устройства приложение временно использует системное по умолчанию и возвращается к выбранному, когда оно появится.

## Настройки по умолчанию

- Модель ответов и классификатора: `qwen3-coder:30b`; Ollama: `http://localhost:11434/api/chat`.
- Whisper: `base`, CPU, язык `ru`. Прогрев модели включён.
- Фильтр речи включён, режим «сбалансированный». Озвучка выключена. Микрофон выключен.
- Скрытие от захвата экрана и закрытие в трей включены.

Модели и устройства меняются в меню (`⋯`) → «Настройки». Имена моделей Ollama должны существовать в `ollama list`.

## База знаний и память

Открывается из меню → «База знаний и долговременная память…». Поддерживаются PDF с текстовым слоем, DOCX, TXT и Markdown (сканы без OCR не индексируются). В `knowledge.sqlite3` сохраняются извлечённые фрагменты, метаданные и (при включении) embeddings; исходные файлы не перемещаются и не изменяются, удаление документа из базы их не удаляет.

Память — это явные заметки с категориями и тегами; автоматического сохранения сведений из переписки нет. Материалы добавляются только в текущий запрос, не пишутся в историю и помечаются для модели как недоверенные справочные данные.

Для семантического поиска выберите embedding-модель (Настройки → Модели), включите поиск (Настройки → Знания) и импортируйте документы; при позднем выборе модели используйте «Переиндексировать embeddings». Без неё работает локальный полнотекстовый поиск FTS5. Подробности и границы приватности: [docs/KNOWLEDGE_R22.md](docs/KNOWLEDGE_R22.md).

## Аудиоисточники

- Настройки → Голос → «Захватывать микрофон» и выбор устройства. Кнопка обновления находит USB, Bluetooth и 2.4 GHz устройства, подключённые после запуска.
- Windows должна разрешать доступ к микрофону настольным приложениям: Параметры → Конфиденциальность и безопасность → Микрофон.
- Принятые фразы с микрофона обрабатываются так же, как системный звук: могут уходить классификатору и сохраняться в истории. Технические логи текст не содержат.
- Во время озвучки захват приглушается. Для наушников можно разрешить микрофону оставаться активным; это не эхоподавление. Акустическое эхоподавление и голосовое перебивание не реализованы.
- Устройства различаются по backend ID SoundCard; старые настройки по имени мигрируют. Подробности: [docs/AUDIO_R21.md](docs/AUDIO_R21.md).

## Центр диагностики

Меню → «Центр диагностики…»: доступность Ollama и установленные модели, соответствие настроенных ролей, состояние источников звука, Whisper/TTS, целостность SQLite-баз, размер журнала. Проверка идёт в фоне и не блокирует чат. Отчёт можно скопировать; в него не попадают диалоги, речь, документы, память и содержимое логов, а учётные данные и параметры URL Ollama скрываются. Перед отправкой отчёта убедитесь, что имена моделей и адрес можно раскрывать получателю.

## Данные и приватность

Папка `%LOCALAPPDATA%\LocalAssistant\` (меню → «Открыть папку данных и логов»):

| Файл | Что внутри |
|---|---|
| `conversations.sqlite3` | диалоги: принятые фразы и ответы |
| `knowledge.sqlite3` | документы, память, embeddings |
| `settings.json` | настройки |
| `live_assistant.log*` | технический журнал |

- В журнал **не пишется распознанная речь** (только длина фразы). Полный текст включается явно, только для отладки.
- Журнал фильтра хранится в памяти и исчезает при выходе.
- Базы **не шифруются** приложением. Защита зависит от учётной записи Windows и шифрования диска; не импортируйте чувствительные документы на незащищённом устройстве.
- Если вы запускали очень ранние сборки, в которых мог писаться текст в журнал, удалите `live_assistant.log*` из этой папки.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| «Ollama не отвечает» | запустите Ollama; меню → «Проверить Ollama» |
| «Модель не найдена» | `ollama pull <имя>` или выберите установленную в настройках |
| Не слышит звук | Настройки → Голос → источник; порог чувствительности; «Центр диагностики» |
| Слишком много или мало ответов | «Журнал фильтра», режим фильтра, имена помощника |
| Окно пропало | `Ctrl+Alt+H`, значок в трее, повторный запуск программы |
| Нет значка в трее | Параметры Windows → Персонализация → Панель задач → значки в углу |
| Статус защиты «не применила» | обновите Windows; код ошибки записан в журнал |
| Выход «завис» | при задержке аудиодрайвера приложение ждёт безопасного завершения потока и показывает предупреждение; не завершайте процесс принудительно без необходимости |

## Обновление, сборка, публикация

- **Обновление:** закройте приложение, из папки репозитория на ветке `master` запустите `update.bat`. Он проверит, что нет локальных изменений, сделает fast-forward и обновит зависимости в `.venv`. Настройки и история не затрагиваются.
- **Сборка EXE:** `build_exe.bat` (только `.venv`) → `dist\LocalAssistant\LocalAssistant.exe`. CI добавляет к артефакту README, список зависимостей, `VERSION` и точный `requirements-lock-win-py312.txt`.
- **Установщик (необязательно):** [installer/LocalAssistant.iss](installer/LocalAssistant.iss), Inno Setup 6. Собирается в CI заданием `windows-installer` или вручную после `build_exe.bat`: `ISCC /DAppVersion=<версия> installer\LocalAssistant.iss`. Данные в `%LOCALAPPDATA%\LocalAssistant` при удалении программы сохраняются.
- **Публикация в master:** после `setup.bat` запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\publish_to_master.ps1`. Скрипт выполнит компиляцию и полный набор тестов; при ошибке публикация остановится. Затем клонирует актуальный `master` во временную папку, перенесёт исходники, создаст обычный коммит и сделает `git push` без принудительной перезаписи.

## Разработка и проверка

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py assistant tests tools
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют фильтрацию, хранение диалогов и настроек, Ollama-клиент, лимит контекста, отмену запросов, прогрев, озвучку, трей и автозапуск, защиту от захвата (включая переиспользование HWND), базу знаний и аудио-логику через подставные объекты. В GitHub Actions установлены PySide6 и Qt offscreen, поэтому тесты с Qt выполняются, а не пропускаются.

Что тесты **не** заменяют: реальный системный трей, аудиоустройства, захват экрана программами трансляции, сборка и установщик на чистой машине. Для этого — [docs/MANUAL_QA.md](docs/MANUAL_QA.md); пройдите его перед выпуском.

Технические документы: [docs/RELIABILITY_R20.md](docs/RELIABILITY_R20.md) (отмена и надёжность), [docs/AUDIO_R21.md](docs/AUDIO_R21.md) (аудиоисточники), [docs/KNOWLEDGE_R22.md](docs/KNOWLEDGE_R22.md) (база знаний).

`requirements.txt` содержит минимальные версии; точный набор для воспроизводимой сборки CI сохраняет в `requirements-lock-win-py312.txt`.
