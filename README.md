# LocalAssistant

**Что нового в r23.7:** обнаружение аудиоустройств вынесено в фоновый поток, чтобы медленное перечисление Bluetooth/USB endpoint не подвешивало настройки. Результаты безопасно применяются в интерфейсе, несохранённый выбор сохраняется; закрытие окна не ожидает зависший backend.

**Единый локальный голосовой помощник для Windows** — объединённая версия возможностей LocalAssistant r16 и LiveAssistant 1.0.0. Приложение может одновременно захватывать системный звук и выбранный микрофон независимыми аудиопотоками, распознаёт речь через faster-whisper, фильтрует фразы и отвечает через локальную Ollama. По умолчанию приложение обращается к локальной Ollama. Если в настройках указан удалённый адрес Ollama, сообщения, контекст и текст для классификации отправляются на этот сервер; выбирайте такой адрес только если доверяете его владельцу. Технические логи по умолчанию маскируют распознанную речь, но принятые сообщения и ответы сохраняются в локальной SQLite-истории.

## Что нового в r22 — Local Knowledge & Memory

- Добавлена доступная из меню «База знаний и долговременная память…» локальная библиотека документов и ручных заметок с отдельной вкладкой проверки поиска.
- Импортируются PDF с текстовым слоем, DOCX, TXT и Markdown. Для PDF и DOCX используются `pypdf` и `python-docx`; сканированные PDF без OCR не индексируются.
- Документы извлекаются локально, разбиваются на фрагменты с указанием страницы/абзаца/таблицы и индексируются в отдельной `knowledge.sqlite3`. Полнотекстовый поиск использует SQLite FTS5, а при отсутствии FTS5 — безопасный LIKE fallback.
- Добавлена явная долговременная память с категориями и тегами. Записи создаются, редактируются и удаляются пользователем; количество записей, добавляемых в контекст ответа, настраивается отдельно. Автоматическое сохранение личных сведений из переписки не выполняется.
- Опциональный семантический поиск через отдельную Ollama embedding-модель. Без неё полнотекстовый поиск продолжает работать; векторный индекс можно создать/обновить для выбранного документа. До отправки query embedding приложение проверяет, есть ли для выбранной модели хотя бы один индексированный документ, поэтому пустая база не вызывает лишний запрос Ollama.
- Индексация embeddings использует staging-таблицу и атомарную публикацию: при ошибке сети существующий векторный индекс сохраняется.
- Embedding-запросы используют общий сериализованный клиент Ollama, поэтому не конкурируют с генерацией, классификацией и прогревом; отмена активной задачи закрывает именно принадлежащий ей HTTP-ответ. Отмена, пока embedding ожидает общую очередь, не прерывает текущий чат. Отмена индексации проверяется между пакетами и перед атомарной публикацией; предыдущий индекс сохраняется.
- Документные фрагменты и записи памяти добавляются только в текущий запрос, не записываются обратно в историю как текст пользователя и помечаются как недоверенные справочные данные. Дополнительная политика недоверенных источников закрепляется в системном сообщении, а не только в пользовательском блоке. Перед добавлением материалов учитывается оставшийся бюджет контекста.
- Семантическое ранжирование использует top-k heap: во время сканирования загружаются только ID и векторы, а текст извлекается из SQLite лишь для лучших результатов. Скан ограничен 20 000 кандидатов и адаптивным бюджетом до 64 МиБ сырых векторов.
- Добавлена миграция схемы базы знаний (`PRAGMA user_version`) и индекса памяти с поддержкой поиска по тегам.

## Что нового в r21 — Audio Intelligence Foundation

- Системный звук и микрофон теперь являются независимыми аудиоисточниками. Их можно включать отдельно или одновременно в Настройки → Голос. Микрофон по умолчанию выключен для сохранения прежнего поведения и приватности.
- Каждый источник имеет собственный поток захвата, сегментатор, ограниченную очередь и политику переподключения. Один общий Whisper worker обрабатывает фразы последовательно, чтобы не вызывать один экземпляр модели конкурентно.
- В списках устройств сохраняются backend ID SoundCard, а не только отображаемые имена. Для старых настроек сохранён переход по имени; если выбранное устройство исчезло, оно остаётся выбранным и будет повторно обнаруживаться, а захват временно использует системное устройство по умолчанию.
- У каждого источника отдельная оценка уровня и адаптивный энергетический порог. Rolling-percentile noise estimator подстраивает порог к фоновому шуму; гистерезис между началом и окончанием речи снижает дробление тихих слогов. Встроенный VAD faster-whisper продолжает выполнять дополнительную проверку.
- Пауза, закрытие приложения и смена устройства отдельно инвалидируют события соответствующего аудиопотока и отменяют ожидание Whisper между сегментами. Очереди системного звука и микрофона ограничены независимо и обрабатываются по очереди, чтобы один источник не вытеснял другой; фразы старше 30 секунд отбрасываются как неактуальные.
- Источник распознанной фразы показывается в предпросмотре. Микрофон приглушается во время TTS по умолчанию, чтобы ассистент не распознавал собственную озвучку. При использовании наушников можно явно разрешить микрофону оставаться активным; акустическое эхоподавление не реализовано.
- Добавлены независимые настройки выбора устройства, источников аудио и чувствительности. Старый `audio_device` по имени мигрирует без потери выбранного значения.

## Что нового в r20 — Reliability Foundation

- Поток прогрева не запускается, если приложение завершает работу во время проверки Ollama. Создание и запуск background-потока синхронизированы, чтобы исключить гонку между стартом потока и Stop.

- Кнопка «Стоп» теперь отменяет всю операцию, включая ожидание локального классификатора, а не только поток генерации ответа.
- Запрос классификатора выполняется с отменяемым HTTP-ответом; отмена не показывается пользователю как ошибка Ollama.
- Фоновый прогрев модели прекращается при поступлении интерактивного сообщения. Прогрев, проверка Ollama, классификация и генерация сериализованы, чтобы не создавать конкурирующие запросы через общий HTTP-сеанс и к одному model runner.
- Повторная проверка Ollama проходит через очередь процессора, а не через отдельный неуправляемый поток.
- Изменение аудиоустройства больше не блокирует интерфейс ожиданием до пяти секунд. Новый AudioWorker создаётся после фактического завершения старого QThread.
- Поток Whisper не является daemon-потоком: приложение дожидается завершения текущего native inference, прежде чем владеющий QThread завершится. При этом обработчик прекращает потреблять новые сегменты сразу после сигнала остановки и не публикует результат закрываемого потока.
- Повторная генерация удаляет только ответ, относящийся к последнему сообщению пользователя. Ответ на более ранний вопрос не удаляется, если последнее сообщение ещё осталось без ответа.
- Добавлены регрессионные тесты отмены запросов и безопасной повторной генерации.

## Что вошло в объединённую версию

### Знания и память (r22)
- Отдельная локальная SQLite-база документов и явной долговременной памяти.
- Импорт PDF/DOCX/TXT/Markdown, разбиение на фрагменты и источник-локаторы.
- Полнотекстовый поиск FTS5 с LIKE fallback; опциональное семантическое ранжирование через Ollama embeddings.
- При поиске используются теги памяти; векторная переиндексация выполняется транзакционно через staging.
- Материалы добавляются в контекст только на время текущего запроса и не изменяют сохранённую историю диалога.

### Голос и ответы
- Захват системного звука Windows через SoundCard loopback и опциональный захват физического микрофона через отдельный входной endpoint. Источники можно использовать одновременно.
- Распознавание faster-whisper на CPU или CUDA; поддерживаются имена моделей и языковые коды Whisper.
- Захват аудио и распознавание разнесены по потокам; ограниченная очередь не позволяет копить бесконечную задержку.
- Фильтрация в два этапа: правила и локальная модель-классификатор Ollama для неоднозначных фраз. Режимы «сбалансированный» и «быстрый», фильтр галлюцинаций Whisper и защита от повторов.
- Журнал последних решений фильтра с возможностью вручную отправить пропущенную фразу.
- Потоковые ответы Ollama, остановка и повтор генерации, скрытие `<think>`-блоков, копирование кодовых блоков.
- Ограничение истории по бюджету токенов, индикаторы скорости и заполнения контекста, прогрев модели и повторная проверка Ollama.
- История диалогов SQLite: создание, переключение, поиск, переименование, удаление и экспорт в Markdown.
- Офлайн-озвучка через Windows SAPI с настройкой голоса, скорости и громкости; защита от акустической обратной связи.

### Интеграция с Windows
- Системный трей с меню для показа окна, паузы прослушивания, переключения озвучки, настроек и выхода.
- Закрытие окна сворачивает его в трей; приложение продолжает работать. Поведение можно изменить в настройках.
- Защита от повторного запуска: эксклюзивная межпроцессная блокировка `QLockFile` плюс локальный IPC-канал `QLocalServer`; второй запуск активирует уже работающий экземпляр. Поддерживается обнаружение старого экземпляра LiveAssistant на время обновления.
- Автозапуск вместе с Windows без прав администратора, запуск сразу в трей. Старое значение автозапуска LiveAssistant мигрирует при изменении настройки.
- Отслеживание смены устройства вывода и микрофона Windows; при потере выбранного устройства приложение временно использует системное по умолчанию и возвращается к выбранному устройству после его появления. В настройках сохраняются backend ID, а display-name используется для миграции старых настроек.
- Защита всех верхнеуровневых окон от программного захвата экрана через `SetWindowDisplayAffinity`, если это поддерживается Windows. Статус защиты можно посмотреть в настройках.
- Иконка приложения и системного трея.

### Надёжность и приватность
- Текст распознанной речи не попадает в технические логи по умолчанию; вместо него логируется длина фразы. Полный текст включается пользователем только для отладки.
- Настройки хранятся в `%LOCALAPPDATA%\LocalAssistant\settings.json`, история — в `conversations.sqlite3`, технический журнал — в `live_assistant.log*`.
- Исправлена очередь голосовых фраз: текст хранится непосредственно в событии очереди, поэтому отменённая фраза не может «перепрыгнуть» через переключение диалога.
- Состояние TTS и поколения процесса синхронизированы одной блокировкой, чтобы остановка не могла быть перезаписана устаревшим состоянием запуска.

Технические решения r20, границы отмены и обязательные проверки перед релизом описаны в [`docs/RELIABILITY_R20.md`](docs/RELIABILITY_R20.md). Архитектура библиотеки знаний и границы её приватности описаны в [`docs/KNOWLEDGE_R22.md`](docs/KNOWLEDGE_R22.md).

## Установка на Windows

### 1. Установите Python и Ollama

Рекомендуется **Python 3.12 x64**. Установите Python с включённым Python Launcher (`py`) и Ollama для Windows.

Проверьте доступные модели:

```powershell
ollama list
```

Например, скачайте модель ответов:

```powershell
ollama pull qwen3-coder:30b
```

Ollama обычно запускается в фоне автоматически. Если она не запущена, откройте Ollama из меню «Пуск». Команду `ollama serve` используйте только если сервер ещё не работает: занятый порт `11434` означает, что сервер уже слушает этот адрес.

### 2. Получите проект с GitHub

Откройте PowerShell и выполните:

```powershell
cd "$HOME\Desktop"
git clone https://github.com/S1nuso1d/LocalAssistantRefactor.git LocalAssistant
cd .\LocalAssistant
git switch master
```

Если папка `LocalAssistant` уже существует, не клонируйте поверх неё: выполните в ней `git pull --ff-only origin master`.

### 3. Установите зависимости

Дважды щёлкните `setup.bat` или выполните из PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Скрипт создаёт виртуальное окружение внутри проекта и устанавливает все зависимости. Активация `Activate.ps1` не нужна.

### 4. Запустите приложение

**Обычный запуск без консольного окна:**

```powershell
.\run.bat
```

**Запуск с видимым окном PowerShell для диагностики:**

```powershell
.\.venv\Scripts\python.exe .\main.py
```

При первом запуске faster-whisper скачает выбранную модель распознавания, поэтому понадобится интернет. После запуска значок появится в области уведомлений Windows. Если его не видно, нажмите стрелку `^` рядом с часами.

## Настройки по умолчанию

- Модель ответов и классификатора: `qwen3-coder:30b`.
- Ollama: `http://localhost:11434/api/chat`.
- Whisper: `base`, CPU, язык `ru`.
- Прогрев модели включён.
- Фильтр речи включён, режим «сбалансированный».
- Озвучка выключена до явного включения пользователем.
- Скрытие от программного захвата экрана и закрытие в трей включены.

Модели и устройства можно изменить в меню приложения → «Настройки». Имена моделей Ollama должны существовать в `ollama list`.

База знаний и долговременная память открываются из меню `⋯` → «База знаний и долговременная память…». Добавленные документы копируются не в исходные папки: в `knowledge.sqlite3` сохраняются извлечённые текстовые фрагменты, метаданные и (при включении) embeddings. Удаление документа из базы не удаляет исходный файл.

Для семантического поиска выберите embedding-модель во вкладке Настройки → Модели, включите его во вкладке Настройки → Знания и импортируйте документы. Если модель была выбрана позже, используйте «Переиндексировать embeddings» для документа. Без embedding-модели остаётся доступен локальный полнотекстовый поиск FTS5.

## Публикация объединённой версии в master

Если вы получили этот архив для публикации, откройте PowerShell в распакованной папке проекта и запустите:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\publish_to_master.ps1
```

Перед публикацией запустите `setup.bat`, чтобы создать `.venv` и установить зависимости. Затем скрипт выполнит компиляцию и полный набор тестов на этой Windows-машине; при ошибке публикация остановится. Если тесты пройдены, скрипт клонирует актуальный `master` во временную папку, переносит в него исходники этой версии, создаёт обычный коммит и выполняет `git push` без принудительной перезаписи истории. Для отправки изменений GitHub должен быть доступен, а Git должен иметь настроенную авторизацию. Если push отклонён из-за новых коммитов в `master`, проверьте расхождение и повторите публикацию.

## Сборка EXE

После установки зависимостей запустите `build_exe.bat`. При успехе исполняемый файл будет создан в `dist\LocalAssistant\LocalAssistant.exe`. В Windows CI к артефакту также добавляются README, исходный список зависимостей, версия и точный `requirements-lock-win-py312.txt` для окружения сборки. Модели Whisper не включаются в EXE и скачиваются при первом запуске. Сам факт наличия скрипта сборки не означает, что конкретная сборка уже проверена на вашем компьютере.

## Аудиоисточники и приватность

- В настройках → Голос включите «Захватывать микрофон» и выберите физический микрофон. Системный звук и микрофон могут работать вместе или независимо.
- Доступ к микрофону должен быть разрешён для настольных приложений в Windows: Параметры → Конфиденциальность и безопасность → Микрофон.
- Микрофон по умолчанию выключен. При включении система обрабатывает его поток так же, как системный звук: распознанные обращения могут отправляться классификатору и сохраняться в истории, если они приняты. Технические логи маскируют текст по умолчанию.
- Во время TTS системный звук и микрофон приглушаются по умолчанию. Для сценария с наушниками можно явно разрешить микрофону оставаться активным; это не является эхоподавлением. Используйте наушники, чтобы динамики не попадали обратно в микрофон. Акустическое эхоподавление и голосовое перебивание относятся к следующему этапу.
- Backend ID SoundCard предпочтительнее имени: библиотека описывает ID как уникальный, но backend-dependent идентификатор. При миграции старых настроек используется точное совпадение имени; после сохранения — точный ID. См. [документацию SoundCard](https://soundcard.readthedocs.io/en/latest/).

## Тесты и разработка

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py assistant tests tools
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют фильтрацию, хранение диалогов и настроек, нормализацию Ollama URL, лимит контекста, отмену запросов Ollama, прогрев, TTS, трэй/автозапуск и Windows API через подставные объекты. Проверка реального системного трея, аудиоустройств, захвата экрана и сборки EXE всё равно требует ручного тестирования в Windows.

В GitHub Actions установлены PySide6 и Qt offscreen, поэтому поведенческие тесты процессора тоже выполняются, а не пропускаются из-за отсутствия Qt.

## Ограничения защиты экрана

`SetWindowDisplayAffinity` скрывает окна приложения только от совместимого программного захвата. Значок трея и панель задач принадлежат Windows и могут быть видны при демонстрации всего экрана. Функция не скрывает изображение от камеры, направленной на монитор, или аппаратной карты захвата. Проверьте поведение в конкретном приложении трансляции до использования.

## Обновление проекта

Закройте LocalAssistant, затем из папки репозитория на ветке `master` запустите `update.bat`. Скрипт проверит, что рабочая копия не содержит незакоммиченных или неотслеживаемых файлов, выполнит только fast-forward обновление и обновит зависимости в `.venv`. Настройки и история в `%LOCALAPPDATA%\LocalAssistant` не затрагиваются.

## Восстановление аудиосистемы (r18)

- Переоткрытие loopback-потока при смене системного устройства вывода.
- Отслеживание вручную выбранного устройства: если оно временно отключилось, используется системное устройство по умолчанию; когда выбранное устройство возвращается, приложение автоматически переключается обратно.
- Изменение выбора устройства в настройках применяется без перезапуска приложения.
- Очередь и находящиеся в обработке фразы помечаются поколением аудиопотока. После переключения устройства или паузы результат распознавания от старого потока отбрасывается.
- После нескольких последовательных ошибок захвата применяется экспоненциальная задержка повторного подключения от 1 до 15 секунд; после восстановления она сбрасывается.
- Остановка и пауза не пропускают старые фразы в следующий активный сеанс.

## Подготовка релиза (r19)

- CI запускает тесты на Ubuntu и Windows с Python 3.12 и установленным PySide6, поэтому тесты MessageProcessor не должны незаметно пропускаться из-за отсутствия Qt.
- Отдельная задача Windows CI собирает приложение через PyInstaller и публикует папку `LocalAssistant` как артефакт сборки.
- `build_exe.bat` использует только `.venv`, а не случайный системный Python.
- `update.bat` выполняет безопасное fast-forward обновление `master` и не перезаписывает локальные изменения.

Проверка реальной смены Bluetooth/USB/2.4 GHz устройств, поведения трея, автозапуска и защиты экрана всё равно требует ручного запуска на Windows. Успешная сборка CI не является подтверждением работы аудиоустройств на каждом компьютере.


## Ограничения проверки r21

В контейнере разработки выполнены компиляция Python и доступная часть unittest: обнаружено 141 тест, 113 прошли, 28 пропущены из-за отсутствующих PySide6 и аудиозависимостей. Перед публикацией релиза обязательны успешные Windows CI jobs с полным набором зависимостей и ручная проверка одновременной записи микрофона и loopback на целевом компьютере.


## Ограничения и проверка r22

- PDF/DOCX extraction требует `pypdf` и `python-docx`; оба пакета устанавливаются из `requirements.txt`. PDF без текстового слоя не распознаётся, OCR не входит в r22.
- Семантический поиск отключён по умолчанию и требует отдельную Ollama embedding-модель. Фрагменты документов и поисковый запрос отправляются на адрес Ollama, указанный в настройках. Если адрес удалённый, владелец этого сервера получает переданные данные.
- Полнотекстовый поиск работает локально и не требует embedding-модели. При ошибке embeddings поиск автоматически остаётся на FTS/LIKE. Обычный чат продолжает запускаться даже при недоступной/повреждённой БД знаний; в этом случае retrieval отключается до исправления базы.
- Сканирование semantic index ограничено 20 000 кандидатами и адаптивным бюджетом до 64 МиБ сырых векторов; при очень большой размерности число кандидатов автоматически уменьшается. Полнотекстовый поиск документов не имеет этого ограничения. Во время ранжирования загружаются только ID и векторы; полный текст извлекается лишь для top-k.
- r22 добавляет схему `knowledge.sqlite3`; существующая история `conversations.sqlite3` не изменяется. База знаний сама мигрирует схему через `PRAGMA user_version`, а исходные документы остаются на исходных местах. Отмена импорта проверяется при извлечении и вставке; отменённая транзакция не оставляет частичный документ. При отмене embeddings существующий индекс сохраняется.
- Проверка в контейнере разработки: 182 теста обнаружено, 152 пройдено, 30 пропущено из-за отсутствия PySide6 и аудиозависимостей; компиляция Python пройдена на Python 3.13.5. Это не заменяет запуск целевого Python 3.12, Windows CI и реальную проверку Qt/Ollama на компьютере пользователя.
- Важное ограничение хранения: `knowledge.sqlite3` и `conversations.sqlite3` не шифруются приложением на диске. Защита зависит от учётной записи Windows и шифрования системного диска; не импортируйте чувствительные документы на устройстве без соответствующей защиты.
- Перед выпуском обязательны тесты на Windows с установленными зависимостями и ручная проверка импорта PDF/DOCX, поиска по документам, управления памятью, отмены импорта/индексации и запросов к Ollama.


## Центр диагностики (r23)

Откройте значок активности в заголовке или меню «Центр диагностики…». Проверка Ollama выполняется коротким запросом `/api/tags` без загрузки модели. Целостность обеих SQLite-баз проверяется через `PRAGMA quick_check` в режиме read-only. В диагностический отчёт не включаются диалоги, документы, память или содержимое технических логов. Перед отправкой отчёта убедитесь, что отображаемые имена моделей и endpoint можно раскрывать получателю.

История диалогов подгружается порциями по 100 записей; дополнительная порция загружается кнопкой «Загрузить ещё».
