# LocalAssistantRefactor — dark glass chat

Модульный локальный голосовой ассистент: PySide6, SoundCard loopback, faster-whisper и Ollama.

## Возможности

Build: `2026.11.19-r15`

- Полупрозрачный тёмный интерфейс с попыткой включить Windows Acrylic.
- Чат с Markdown-ответами (код, списки, заголовки, таблицы), анимацией сообщений и индикатором генерации.
- Потоковый вывод Ollama, кнопка остановки генерации, копирование ответа и повтор последнего ответа.
- Отдельный поток захвата/распознавания аудио и очередь обработки речевых фраз.
- Правила фильтрации и локальная классификация неоднозначных фраз.
- История диалогов в SQLite: новый диалог, переименование, удаление, переключение, поиск по тексту сообщений.
- JSON-настройки под `%LOCALAPPDATA%\LocalAssistant\settings.json`.
- База чатов под `%LOCALAPPDATA%\LocalAssistant\conversations.sqlite3`.
- Настройки (вкладки «Модели», «Голос», «Окно», «Ассистент»): адрес Ollama, модели, размер контекста, температура, системный промпт, устройство и размер Whisper (CPU/CUDA), имена ассистента, порог речи, горячая клавиша, прозрачность, режимы окна и приватность. Список моделей Ollama подгружается в фоне.

## Что нового в r15

Исправления моей же валидации настроек из r7, которая оказалась слишком строгой или недостаточно умной:

- **Модель Whisper** — любое имя (`large-v3-turbo`, `distil-large-v3`, путь к папке), а не только пять значений из списка; раньше любое другое имя молча превращалось в `base`. Ошибка неверного имени покажется при загрузке модели. `large-v3-turbo` требует достаточно свежей версии faster-whisper.
- **Язык распознавания** — любой код Whisper (`de`, `zh`, `ja`…) или `auto`; в списке настроек теперь 12 языков. Код языка используется и для выбора голоса озвучки.
- **Адрес Ollama** понимает `localhost:11434`, `http://host:11434`, адрес за обратным прокси и случайно вставленные `/api/generate` или `/api/tags`; всё приводится к `…/api/chat`. Окно настроек применяет то же правило при загрузке списка моделей.
- 71 тест без Qt + 10 тестов процессора (пропускаются без PySide6).

## Что нового в r14

- **Исправление приватности.** Начиная с r7 приложение писало лог в файл, и в него попадал распознанный текст всего, что звучит в системе (в том числе закрытых созвонов). Теперь по умолчанию в лог идёт только длина фразы (`<27 симв.>`). Полный текст включается явно: Настройки → Голос → «Писать распознанный текст в лог (для отладки)». Тест-страж следит, чтобы вызовы лога с речью проходили через `describe_text`.
- **Если вы уже запускали r7–r13:** удалите старые логи `live_assistant.log*` в `%LOCALAPPDATA%\LocalAssistant\` — меню → «Открыть папку данных и логов». Они могли содержать распознанные фразы.
- Что хранится на диске: `conversations.sqlite3` — только диалоги (принятые фразы и ответы); `settings.json` — настройки. Журнал фильтра живёт только в памяти и пропадает при закрытии.
- 66 тестов без Qt + 10 тестов процессора (пропускаются без PySide6).

## Что нового в r13

- **Прогрев модели:** при запуске, если Ollama готова, модель ответов загружается в память фоном (пустой запрос к `/api/generate`), поэтому первый голосовой вопрос не ждёт десятки секунд загрузки 30B-модели. Статус: «Загружаю модель в память…» → «Модель загружена и готова». Отключается в Настройки → Модели → «Прогрев» (модель занимает память, пока приложение открыто). Прогревается только модель ответов, не классификатор.
- **Повторная проверка Ollama без перезапуска:** меню → «Проверить Ollama»; запускается и автоматически после смены адреса или моделей в настройках.
- `requirements.txt`: нижние границы версий (не точные пины); `soundcard>=0.4.4` — в нём исправлена запись loopback на NumPy 2.x.
- 63 теста без Qt + 10 тестов процессора (пропускаются без PySide6).

## Что нового в r12

- **История режется по токенам, а не только по числу сообщений.** Раньше несколько больших вставленных текстов переполняли окно, и Ollama молча отбрасывала самое старое — вместе с системным промптом. Теперь в запрос попадают самые новые сообщения, которые помещаются в `num_ctx` минус запас на ответ (четверть окна) и минус системный промпт. Последнее сообщение остаётся всегда; «осиротевший» ответ ассистента в начале истории убирается.
- **Статус после ответа** показывает скорость и заполнение контекста: `Ответ готов · модель · 5.2 с · 38 ток/с · контекст ≈3.1k/8.2k`, а при обрезке — сколько старых сообщений не вошло. Заполнение берётся как максимум из оценки приложения и `prompt_eval_count` Ollama, потому что Ollama не учитывает токены, взятые из KV-кэша, и может занижать цифру.
- Если Ollama сама вычислила ≥95% окна, один раз на диалог появляется предупреждение с советом увеличить «Контекст» или начать новый диалог.
- Оценка токенов грубая (≈3 символа на токен), намеренно с запасом; на коде и редких словах реальное число может отличаться.
- 58 тестов без Qt (+ 8 тестов процессора, пропускаются без PySide6).

## Что нового в r11

- **Журнал фильтра** (меню → «Журнал фильтра…»): последние 60 фраз с вердиктом и причиной — принято правилами / моделью, отсеяно правилами / моделью, повтор, классификатор недоступен, ненадёжное распознавание (похоже на музыку или шум), устарела в очереди, сброшена кнопкой «Стоп». Окно обновляется вживую; двойной клик или «Ответить на эту фразу» отправляет пропущенную фразу ассистенту вручную. Так удобно подбирать режим фильтра на реальном звуке.
- `tests/test_processor.py` — поведенческие тесты процессора (нужен установленный PySide6; без него пропускаются). **В моей среде они не запускались с настоящим Qt** — логику я проверял на заглушках; если тест упадёт у вас, пришлите вывод.
- 52 юнит-теста без Qt + 6 тестов процессора (пропускаются без PySide6).

## Что нового в r10

- **Озвучка ответов** (офлайн, только Windows): встроенные голоса SAPI через PowerShell, без новых зависимостей. Режимы: выключена / только ответы на голосовые вопросы / все ответы. Переключается в меню («Озвучка: …») и в Настройки → Озвучка (скорость, громкость, имя голоса).
- Для озвучки очищается Markdown: код заменяется фразой «Пример кода показан на экране», убираются ссылки, эмодзи, разметка и блоки `<think>`.
- **Защита от эха:** пока ассистент говорит (и 0,8 с после), захват системного звука приглушается — он не отвечает сам себе. Минус: голосом перебить его нельзя; `Esc` или кнопка «Стоп» прерывают речь, как и новое сообщение или смена диалога.
- Русский голос нужно установить в Windows: Параметры → Время и язык → Речь. Без него будет голос по умолчанию, и русский текст может звучать плохо.
- 51 юнит-тест. Сама речь (PowerShell + SAPI) в этой среде не проверялась — только логика на подставном процессе.

## Что нового в r8

- **Режим фильтра** (Настройки → Голос): «Сбалансированный» (по умолчанию) принимает по правилам только явные обращения — с «?» или повелительные («объясни…»); фразы вида «как он туда попал» из видео уходят на классификатор. «Быстрый» — прежнее поведение.
- Классификатор видит две последние реплики диалога, поэтому короткие уточнения («а подробнее?») распознаются как продолжение разговора.
- Распознавание речи вынесено в отдельный поток: захват звука не останавливается, пока Whisper работает. Очередь ограничена (3), при перегрузке отбрасываются самые старые фразы.
- Стриминг ответа перерисовывается реже на длинных текстах (45 → 260 мс), поэтому интерфейс не тормозит на больших ответах.
- 35 юнит-тестов (без Qt и аудио).

## Что нового в r7

**Функции**
- Многострочное поле ввода (Enter — отправить, Shift+Enter — новая строка), растёт вместе с текстом.
- Окно истории с живым поиском по названиям и тексту сообщений (`Ctrl+K`); экспорт диалога в Markdown (`Ctrl+E`).
- Горячие клавиши: `Ctrl+N` новый диалог, `Ctrl+K` история, `Ctrl+,` настройки, `Ctrl+L` фокус на ввод, `Esc` остановить генерацию.
- Блоки `<think>…</think>` моделей-рассуждателей скрываются в чате и не попадают обратно в контекст.
- Явный `num_ctx` (по умолчанию 8192): Ollama иначе молча обрезает длинные диалоги, теряя системный промпт.
- Проверка Ollama при запуске: понятное сообщение, если сервер не запущен или модель не скачана; при 404 подсказывается `ollama pull`.
- «Повторить ответ» больше не теряет старый ответ, если новая генерация не удалась.
- Очередь голосовых фраз ограничена (2): во время долгого ответа не копятся устаревшие вопросы; «Стоп» очищает очередь.
- Ошибки классификатора показываются в статусе, а не спамят чат при фоновом аудио.
- Расширенный фильтр галлюцинаций Whisper («Субтитры сделал…», «Спасибо за просмотр» и т. п.) и отсев ненадёжных сегментов.
- Pre-roll перед фразой (не обрезается начало слова); во время паузы звуковое устройство продолжает вычитываться, поэтому после возобновления нет лавины старого звука.
- Настройки проверяются и приводятся к допустимым значениям; повреждённый `settings.json` сохраняется как `.bad`.
- Положение и размер окна запоминаются; переключатель «Скрывать окно от захвата экрана».
- Лог в `%LOCALAPPDATA%\LocalAssistant\live_assistant.log`.

**Интерфейс**
- Пузыри: у пользователя — акцентный градиент, у ассистента — «стеклянная» карточка; время у каждого сообщения.
- Статус не раздувает шапку (обрезается с «…»); кнопки «Новый диалог» и «История» в шапке; «Стоп» рядом с «Отправить».
- Волна перенесена в подвал и «гаснет» на паузе; подсказка горячей клавиши показывает реальное сочетание из настроек.
- Автопрокрутка не мешает читать ранние сообщения во время стриминга.
- Тёмные тултипы, вкладки в настройках.

## Запуск в Windows PowerShell

В активном виртуальном окружении из папки проекта:

```powershell
python -m pip install -r requirements.txt
python -m compileall -q main.py assistant tests
python -m unittest discover -s tests -v
python main.py
```

В Ollama должны быть доступны модели, указанные в настройках. Изначально используется `qwen3-coder:30b` и для ответов, и для классификатора; это можно поменять в меню `⋯` → `Настройки`.

Горячая клавиша по умолчанию — `Ctrl+Shift+Space`. Ручные сообщения в поле ввода обходят фильтр голосового намерения, а голосовые фразы сперва проверяются фильтром.

## Файлы

- `main.py` — запуск Qt.
- `assistant/ui.py` — чат, Markdown, анимации, меню, Acrylic и управление окном.
- `assistant/audio_worker.py` — захват системного звука и Whisper.
- `assistant/processor.py` — последовательная очередь фраз, отмена и потоковая генерация.
- `assistant/ollama_client.py` — NDJSON streaming API, классификация, список моделей, отмена активного HTTP-запроса.
- `assistant/speech_filter.py` — правила и защита от дублей.
- `assistant/conversation_store.py` — SQLite.
- `assistant/settings_store.py` — настройки в JSON.
- `assistant/settings_dialog.py` — окно настроек (вкладки).
- `assistant/history_dialog.py` — окно истории с поиском.
- `assistant/segmenter.py` — выделение фраз из аудиопотока и отсев ненадёжных сегментов Whisper (без Qt и аудио, покрыто тестами).
- `assistant/text_utils.py` — `<think>`-блоки, форматирование времени и имён файлов.
- `assistant/config.py` — значения по умолчанию для совместимости.

## Примечания

- Окно исключается из поддерживаемых API захвата экрана только best-effort; это не гарантирует скрытие в каждом приложении видеосвязи.
- Windows Acrylic использует недокументированный API и может не работать на некоторых версиях Windows; резервный тёмный полупрозрачный фон остаётся.
- При выборе другого аудиоустройства или размера Whisper аудиопоток перезапускается, поэтому загрузка Whisper может занять несколько секунд.
- Юнит-тесты не требуют Qt и аудио (`python -m unittest discover -s tests`); сам интерфейс нужно проверять вручную.
- Синтаксическая проверка не заменяет тест на компьютере с фактическим аудиоустройством и работающим Ollama.
