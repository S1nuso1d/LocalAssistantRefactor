# LocalAssistant r20 — Reliability Foundation

## Цель этапа

r20 не добавляет новые пользовательские функции. Его задача — сделать управление уже существующими голосовыми, сетевыми и UI-процессами предсказуемым при отмене, переключении устройств, повторной проверке Ollama и завершении приложения.

## Изменения

### Аудиопоток и жизненный цикл Qt

- Перезапуск AudioWorker больше не ждёт завершения старого QThread блокирующим `wait(5000)` в GUI-потоке.
- Старый worker останавливается, а новый создаётся только после сигнала `finished` старого.
- Повторные изменения настроек во время перезапуска объединяются: следующий worker читает последнее состояние SettingsStore.
- Во время закрытия приложения новый worker не создаётся.
- Whisper transcriber является управляемым не-daemon потоком. При завершении AudioWorker устанавливает stop-event и ждёт полного завершения transcriber, чтобы не оставить поток, обращающийся к закрывающимся объектам.
- Итерация Whisper проверяет stop-event между сегментами и прекращает потребление новых сегментов после остановки. Уже выполняющийся native inference нельзя безопасно прервать посреди операции; завершение ждёт возврата текущей операции.
- Тексты из устаревших поколений аудиопотока не публикуются после смены устройства/паузы.

### Отмена пользовательской задачи

- Единый cancellation token создаётся до классификации голосового намерения и действует до конца генерации.
- Кнопка «Стоп» и `Esc` доступны во время классификации, генерации и озвучки.
- Отмена классификации считается штатным завершением, а не ошибкой Ollama.
- Отменённая голосовая фраза не сохраняется как принятое сообщение пользователя.

### Ollama и HTTP lifecycle

- Общая `requests.Session` защищена сериализацией запросов; health-check, warm-up, classifier и streaming chat не используют её параллельно.
- Активный Response хранится отдельно и закрывается при отмене.
- Сравнение Response при очистке защищает от ситуации, когда завершающийся старый запрос сбрасывает ссылку на более новый активный запрос.
- Проверка Ollama проходит через очередь MessageProcessor, а не через неуправляемый отдельный поток. Если shutdown начался до или во время health-check, прогрев не запускается.
- Прогрев не запускается, если приложение завершает работу во время health-check.
- Ссылка на warm-up thread и его запуск синхронизированы одной блокировкой: Stop не может увидеть Thread, который ещё не был запущен, пропустить join и завершить владеющий процессор раньше времени.

### История и повторная генерация

- Повторная генерация удаляет только ответ, который следует за последним сообщением пользователя.
- Если последний вопрос остался без ответа, предыдущий ответ сохраняется.
- Проверка и удаление выполняются в одной транзакции SQLite.
- UI удаляет пузырь ответа только после подтверждения удаления записи из БД.

### Установка и эксплуатация

- `setup.bat`, `run.bat` и `update.bat` проверяют Python 3.12 в `.venv`, не запуская незаметно проект под другим minor-version.
- Windows CI package artifact переименован в r20.
- Публикационный скрипт использует commit `Publish unified LocalAssistant r20` и не выполняет force push.
- Документация предупреждает о передаче сообщений и контекста на удалённый Ollama endpoint, если пользователь явно указал его вместо localhost.

## Проверки в текущей среде

- `compileall`: успешно.
- `unittest discover`: 122 теста обнаружено, 100 пройдено, 22 пропущено из-за отсутствующих PySide6/SoundCard/faster-whisper в текущем Linux-контейнере.
- Дополнительно 21 тест MessageProcessor и AudioWorker выполнены с временными тестовыми заглушками Qt/audio API: все 21 пройден. Это проверяет Python-логику и сценарии, но не заменяет настоящий Qt runtime и физические аудиоустройства.

## Обязательные проверки перед релизом

1. Успешный Windows CI с настоящим PySide6, SoundCard и faster-whisper; тесты MessageProcessor и AudioWorker не должны пропускаться.
2. Настоящий Windows запуск с тестом смены USB / Bluetooth / 2.4 GHz устройств.
3. Изменение аудиоустройства во время долгого Whisper inference: GUI остаётся отзывчивым, новый worker стартует после корректного завершения старого.
4. Отмена голосовой классификации и потоковой генерации кнопкой Stop и `Esc`.
5. Выход из приложения во время warm-up и во время Whisper inference.
6. Повторная генерация после успешного ответа, после ошибки и после незавершённого запроса.
7. Успешная сборка PyInstaller на Windows и запуск собранного EXE.

## Известные ограничения

- Native Whisper inference нельзя безопасно прервать посреди текущего сегмента; shutdown корректно ждёт его завершения, а дальнейшие сегменты больше не запрашиваются.
- Закрытие HTTP Response отменяет warm-up/classifier после получения response headers. Операция подключения/ожидания первых HTTP headers не может быть мгновенно прервана через уже созданный Response; действует настроенный timeout Requests.
- Автоматические unit-тесты не заменяют реальную проверку Windows tray, SetWindowDisplayAffinity, SAPI voice, драйверов и устройств.
- r20 не меняет поведение моделей или параметры CUDA. Сценарий прогрева большой модели должен отдельно проверяться на целевом ПК.
